> 什么时候读：流程中断、信息不足或拿不准如何承接时。

# 边界与故障处理

| 情况 | 动作 |
| --- | --- |
| 用户已经明确主张／选择过编号 | 直接承接，不重开菜单；只有主张未定时才列候选 |
| 用户明确授权推荐或代选 | 根据材料说明理由后推进，不以固定菜单规则阻拦 |
| 只有书摘、观察或未验证想法 | 标明材料类型与来源，可按理解成稿，不强补个人经历 |
| 主张模糊、关键来源缺失 | 每次最多问 1–2 个必要问题；可给带待补标记的结构，不编出完整故事 |
| 没有反常识、五段或收尾问句 | 不构成失败；只检查主张清楚、来源可追、没有虚构 |
| 用户不选、不补或明确结束 | 等待或按其要求结束，不催、不强迫成稿 |
| 需要历史材料 | 只在当前项目授权范围查找；并入第一人称前请用户确认使用 |
| 多人材料或归属不明 | 分开来源，待核对处不署名，不把他人的话写成用户经历 |
| `/共鸣`、`/顺一下`、`/标题` 的依赖缺失 | 见 [dependencies.md](dependencies.md)；目标文件本地→已安装→简版，不自动全局安装 |
| 子模块要求扩选题、保存或上传 | 本次仅执行用户要求的任务范围，跳过上游可选扩展 |
| 风格档案不存在或没有有效反馈 | 按本轮用户表达写，不自动创建或从 AI 稿推断风格 |
| 未启用记录或学习 | 默认不写；本期明确保存要求只授权本期 |
| 已启用但身份未定 | 仅在需要个人读写时确认安全 `profile_id`，不能 `default.md` 混档 |
| 旧目录有个人 memory／风格文件 | 只在用户明确指定迁移时读取，不批量导入 |
| 同一期反复修改 | 沿用 `session_id` 更新同一记录，保留变化说明 |
| 无法写文件／写入失败 | 交付对话结果并说明保存未完成，不声称已落盘 |
| 没有拍摄或发布反馈 | 状态「未知」，成稿不等于已拍、已发或未拍 |
| 用户明确指定胡子哥骨架 | 直接承接该选择，时长与事实边界仍按用户要求，不重复二选一 |
