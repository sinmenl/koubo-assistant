> 什么时候读：流程卡住、出错，或拿不准某种情况怎么处理时。

# 失败与边界情况处理

| 情况 | 动作 |
| --- | --- |
| 安装 dbskill 失败 | 贴失败原因（截断即可），在对话里按同等原则降级执行，不中断 |
| 只有书摘，没有个人判断 | 菜单标「缺个人判断」；可以先 `/灵感` 三刀；门禁阶段最多 2 问补主张或证据 |
| 反常识门禁不过 | 问时刻（最多 2 问），必要时 `/翻旧账`；仍不过就停在补齐，不成稿 |
| 二次分享有主张、没场景 | 同一轮：问「什么时候遇到这种感受」，并列出历史分享供选；用户确认后才写进证据 |
| 用户以为「分享完就结束」 | 提醒：抽象的迭代要先钉回真实时刻，再升级成洞见卡或口播 |
| 用户要求代写感受 | 拒绝；可以帮搭结构，感受处留空 |
| 用户迟迟不选型 | 只催选型，不自行成稿 |
| 多个主题 | 菜单列出；一期一个；其余进洞见卡 |
| 风格档案不存在 | 写口播时用默认骨架；结束时创建并写入首版 |
| 用户不让记风格 / memory | 跳过对应写入，说一句确认 |
| memory 不存在 | `/复盘` 时说「还没有 memory，先跑几期 /口播」；口播结束时再创建并写入 |
| 多人共用一个项目 | 风格档案和 memory 都按 `{用户标识}.md` 分文件，不混写 |
| 「按胡子哥口播」和五段骨架冲突 | 先问用户要哪一套，二选一 |
